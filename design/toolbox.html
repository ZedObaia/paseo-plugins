04

What it's built on

Checked against the Paseo 0.11.4 plugin SDK and Claude Code 2.1.301.

Every part maps to something Paseo or Claude already does

Toolbox tab on a chat addWorkspacePanel with context: "agent", in the workspace and the Explorer
What this chat loaded agent.commands() lists the chat's skills and commands; connector health from our own check
"Used 6× in this chat" The agent.turn_ended hook carries the turn's timeline
Switches Claude's own settings: skillOverrides and enabledPlugins in .claude/settings.local.json, disabledMcpServers for the folder in ~/.claude.json
Apply skills and plugins Send /reload-skills or /reload-plugins to the chat. Both run headless; no restart
Apply connectors paseo agent reload <id> restarts the process and keeps the conversation
New chats before("agent.create") can add connectors and block tools for that one chat
Pill, sidebar dot, sign-in card addComposerPill, addSidebarHeaderItem with a popover, addTimelineRenderer
/toolbox in the composer addSlashCommand

Limits to design around

  • Switches are per workspace, not per chat. Claude reads them from the chat's folder, so every chat in that folder shares them. Paseo usually gives each task its own worktree, so in practice that's one chat.
  • Connector changes restart the chat. Claude can switch an MCP server on and off live, but Paseo doesn't pass that through to plugins. The restart keeps the conversation.
  • Sign-in is the big job. HTTP connectors need OAuth in the browser, with tokens kept where Claude and Codex read them.
  • Codex: connectors first. enabled = false in config.toml. Skills on Codex come later.
